## How it works

The daemon loads one adapter per harness. Each adapter contributes only small primitives (launch, attach, send, interrupt, read usage) and emits harness-native events; `cctui-server` normalises them into the canonical transcript shape before storing and broadcasting them. Session-level capabilities such as fork, mentions, scheduled messages, subagents and rooms are written once in adapter-neutral code.

ACP rows are opt-in per machine (`default_enabled = false`) because each one needs its own CLI installed. They carry their provider family: a Gemini session binds to a Google-family account, Qwen and Goose to the OpenAI family, and the gateway meters usage the same way it does for Claude Code and Codex.

`docs/harness-parity.md` in the repository records where parity holds and where it does not, per capability and per harness.
