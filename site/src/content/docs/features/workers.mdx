## How it works

A dispatcher is an enrolled executor, like a machine: it connects outward and receives dispatch commands. The kube dispatcher instantiates the profile into a Job, writes a per-dispatch Secret the Job owns, and layers the per-run env (session id, reply URL, task payload) onto the worker container. The pod's daemon enrolls as an ephemeral machine with `CCTUI_MACHINE_KEY`, so the session streams into the UI like any other.

The worker contract separates three planes: platform (set by cctui), operator (the pod template and dispatcher config) and tenant (the task payload). Nothing in the tenant plane can change the sandbox.

See [Run on Kubernetes workers](/cctui/getting-started/kubernetes-workers/) for setup.
