## How it works

The daemon tails each session and streams events to the server over its WebSocket. The server stores them, indexes them for search, and fans them out to every open browser and terminal client. Replies travel the other way: the composer posts to the server, the daemon delivers to the harness, and the delivery state (queued, delivered, deduplicated) is shown on the line.

Prompt cache matters, so usage notices and status checks are delivered as ordinary messages rather than spliced into requests, and a keepalive can keep an idle session's cache warm within a tick budget.
