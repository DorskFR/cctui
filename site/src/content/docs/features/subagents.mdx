## How it works

At launch the daemon writes a per-session MCP config pointing at `cctui-daemon mcp-agent --session <id>`, a stdio relay fixed to that session so no session can spawn as another. Tool calls go to the running daemon, which owns the spawn path; the server creates the child, tracks parent and child, and the daemon watches the child's turn until it completes or times out.

Instance-wide limits on children, depth and tree budget are optional (`CCTUI_SPAWN_MAX_*`); by default there is no limit. See the [MCP tools reference](/cctui/reference/mcp-tools/) for parameters.
