## How it works

Each session is bound to an account; the harness is pointed at cctui's gateway, which injects the real credential, counts tokens, prices them from the account's catalog and enforces rate limits and caps per account and per provider. Balancing is explicit: a session fails over when its account is exhausted, or is pool-bound at spawn; there is no implicit cross-account shuffling. Usage is exported on `/metrics` and as JSON for a status bar (`cctui-admin usage --json`).
