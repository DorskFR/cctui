## How it works

A machine is a daemon with a key. The daemon connects outward over WebSocket, so a machine behind NAT or on a laptop that moves between networks still works. The server pushes a `Reconcile` frame with which adapters to run; the daemon reports liveness, sessions and health.

A spawn is a request from the server to one daemon: adapter, working directory, model, permission posture, context, prompt. Pending spawns show as placeholders in the list immediately and fill in as the session starts; a failed launch shows a toast with the reason. Launches wait rather than fail when a model is soft-blocked by a limit.
