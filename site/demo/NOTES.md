# Demo clips: working notes

Stack: compose project `mkt-demo` (UI :8788, API :8790), seeded from
`deploy/local/fixture/` plus the extras here. Everything recorded is the
invented acme fixture; no real session, machine or person appears.

## Reproduce

```sh
source site/demo/env.sh                    # CCTUI_TOKEN, CCTUI_API_URL, COMPOSE_PROJECT_NAME
bash site/demo/seed.sh                     # base fixture + extras (idempotent)
node site/demo/record.mjs hero live-session permissions ...   # one clip per slug, reseeds before each
node site/demo/record.mjs --list
bash site/demo/encode.sh [slug...]         # -> site/public/media/<slug>.{mp4,webp,poster.webp} (GIF=1 adds .gif)
```

`site/demo/up.sh` starts the stack and seeds it. The server must allow the UI origin
(`CCTUI_ALLOWED_ORIGINS`, set by `env.sh`), or the browser WebSocket is refused (403)
and nothing streams live. Build the `pagedemo` plugin first: `cd webui && npm run plugins:local`.
The `pagedemo` plugin is loaded from `deploy/local/plugins` at server start.

## Files

- `lib.mjs` login/launch helpers (Playwright from `../../webui/node_modules`), `api()`, session ids.
- `shot.mjs` one-off screenshot: `node site/demo/shot.mjs /sessions out.png [mobile]`.
- `seed-extra.sql` gap-filling rows (see below); `seed-extra.mjs` macros + an
  account redirect through the API; `seed.sh` runs base + extras.
- `live-driver.mjs` fake daemon (`FakeDaemon`) plus the scripted stories.
- `record.mjs` Playwright recorder (1280x800, mobile 390x844, fake cursor overlay).
- `encode.sh` trims, time-compresses to the budget, encodes, prints a size table.
- `out/` raw webm, frames, probes (gitignored).

## What is faked and how

- **Live motion**: `live-driver.mjs` connects to `/api/v1/daemon/ws` as
  `workstation-01` (key `cctui_m_seed-fixture-workstation-01`) and, for the spawn
  clips, as `ci-runner-02` (`seed-extra.sql` rehashes its key to
  `cctui_m_seed-fixture-ci-runner-02`). It sends real daemon frames:
  `session_started`, `status`, `message`, `tool_use`, `todos`, `token_usage`,
  `permission_request`, `ask_question`, `session_ended`, and answers `spawn`,
  `reply` and `permission_response` commands. The server persists and
  broadcasts them exactly as it would for a real daemon, so the UI is unmodified.
- **Streaming**: `text_delta` is not rendered by the transcript, so streaming is
  whole lines (thinking, tool call, result, text) arriving with human pacing.
- **Permission / question prompts** exist only in server memory; the driver
  raises them and the recording clicks Allow / the option in the real UI.
- **Spawn**: the New session dialog really POSTs `/spawn`; the fake ci-runner-02
  daemon answers the `spawn` command with `session_started` under the pre-minted
  id, then streams a few lines.
- **Subagents**: `heroStory` registers `a0…06` with `parent_local_id` = session 1.
- **Voice**: a 2 s 330 Hz opus tone generated by ffmpeg in `seed.sh` is the
  voice note; the spoken user turn is a `<cctui-session-context voice="spoken">`
  user line.
- **Rooms / peers**: `rooms`, `room_messages`, `sessions.room_id` and
  `<cctui-room>` / `<cctui-peer-message>` user lines.
- **Workers**: `dispatchers` rows (kube-eu online, kube-us offline) and a failed
  `dispatch_records` row with `worker_exit` (OOMKilled, exit 137, log tail).
  The failed card is hidden on the sessions list for every clip but `workers`
  by moving its `created_at` back 8 days.
- **Harnesses**: opencode (`a0…07`, canonical `{"type":...}` rows), gemini/ACP
  (`a0…08`), codex (`a0…04`, rollout `event_msg`/`response_item` rows).
- **Events feed**: `events` rows with `session_name`/`machine_label` details.
- Also seeded: bookmarks (3), context items (rule/memory/prompt), user actions
  ("Needs you" card), guard step on session 3, 200 paged tool rows on session 3,
  a third machine `build-box-03` offline for 2 days, macros, an account redirect.

## Gotchas learned

- `seed-api.mjs` registers sessions 1/2/5 over HTTP, which parks handles in the
  server's in-memory registry that override DB fields in the list (parent_id,
  adapter, metadata show null). `seed.sh` deregisters them
  (`POST /sessions/{id}/deregister` with the machine key) and re-applies
  `seed.sql`; the fake daemon then registers them properly.
- Sessions spawned by the clips onto fixture machines block the base seed's
  machine delete; `seed.sh` removes non-fixture sessions on `c0000000-%` first.
- Pending prompts outlive a crashed recording (5 min); `record.mjs` resolves
  them before each clip.
- The spawn dialog's label input re-fills itself while typing slowly, so the
  label is set with `fill`; the prompt is typed.
- Playwright `selectOption` needs a string label; `selectMachine` resolves the
  option value first.
- Themes are switched through the header picker (`.cell:has(.swatch[data-theme=…])`);
  setting `data-theme` directly is undone by the app.

## Budgets

CLIPS.md: 6–15 s loops (hero ≤35 s), mp4/webm ≤2.5 MB (hero ≤6 MB), webp ≤2 MB,
gif ≤4 MB. `encode.sh` speeds up any clip longer than the limit (`setpts`),
and steps quality down until each file fits; the printed table shows sizes,
seconds and the speed factor.
